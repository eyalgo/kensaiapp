# Changelog — `core/doctrine`

Each entry records a change to what a user of a fresh clone installs, runs, types or reads in `core/doctrine/`. It names the project the change was made under and cites the commits that made it. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **tools** — `core/doctrine/governance/records_name_no_machine.md` states that a record names no machine. No line in a record names the home folder, a path under it or the login name of the machine a run is on, and the file gives the placeholders to write instead. `core/doctrine/task_map.md` routes a run to it. (`97676aa1d`)
- **tools** — `core/doctrine/engineering/testing_doctrine.md` § *A test reads nothing of the machine it runs on* states that a test reads only what is committed beside it or what it makes itself. It names the commit check and the empty home folder that hold the rule, and says that whoever sees a test break the rule fixes it. (`d12a0b308`, `c90bded3d`, `6d0d8ee83`)
- **tools** — `core/doctrine/setup/kensaiapp_structure.md` § *The changelog — one file per product path records what changed for a user of a fresh clone* states where a product path's changelog sits, what earns an entry and which project an entry names. It says which root files are logged in `core/tools/CHANGELOG.md`, what goes under `### Upgrading`, and what a release cut does to the entries. (`643838745`)
- **product-development** — `core/doctrine/engineering/testing_doctrine.md` § *A unit test hands its unit fakes and touches nothing real* states that a unit test hands the unit a fake for every collaborator, through the seam production wires the real one through, and touches no real process, network, clock or file outside a temporary folder the test makes. `core/doctrine/governance/found_while_walking.md` states that a change which edits a module that builds its own collaborators, or whose unit tests touch a real resource, brings that module up to the standard in the same change. `core/doctrine/engineering/languages/README.md` states that the port and fake modules such a fix needs are not a topology decision, so the stage that meets the conflict makes the fix instead of handing it on. The JavaScript, TypeScript and Shell guides state how their language hands a collaborator in and fakes it in a unit test. (`bdb08fbad`, `808ea2bc8`, `930254239`, `947cbd574`)
- **doctrine** — `core/doctrine/engineering/arch_defaults.md` § *The four layers* states four layers a product's SDD may draw on, what each holds and may import, and that `domain` and `ports` reach no process, network, filesystem, environment variable or clock. Each language guide's `conventions.md` under `core/doctrine/engineering/languages/` states that language's form of the layers and points there. (`00bd40e92`, `812771f3d`, `1c9ae810b`)
- **doctrine** — `core/doctrine/engineering/testing_doctrine.md` § *A fake is verified against its port's contract* states that a port has one fake and one contract suite, run against the real adapter and against the fake, and that a fake failing it fails the suite. Each language's testing file states its form of a contract suite, or that it has none for want of a layer 2, and says that no language has a unit-tier sandbox yet. Both runs of a contract suite are layer 2, and a port's fake lives in a test-support module owned with the port. (`e6b09b42c`, `636014cab`, `a6015c317`)

### Changed

- **tools** — The `records-owed` row of `core/doctrine/flow/step_outcome_contract.md` § *The halts* states that, on a `full` card, the chain copies each named item the main checkout's companion does not hold open from the change worktree's companion onto the main checkout's, and commits it there, before it launches `product-docs`. It names the halts the chain gives when it cannot make that copy. (`6c4ecbb25`)
- **tools** — `core/doctrine/flow/step_outcome_contract.md` § *The halts* has a `records-owed` row. It states when the chain reads a `records-owed` halt report from `specs`, `design` or `plan`, when it launches `product-docs` and starts the change again, and each halt that route can end in. `core/doctrine/setup/kensaiapp_structure.md` states that the chain answers such a report rather than only halting on it. (`b9141a575`, `d75ec0197`)
- **doctrine** — The doctrine calls a project's "done" its finish line, in place of the Definition of Done (DoD). The directional trailer for a project with no open station is `Finish-line:`, and the `prd-and-dod` launcher is `prd-and-finish-line`. (`950438dee`)
- **doctrine** — The doctrine calls a project's "done" its Definition of Done, DoD for short, in place of Agari 上がり. The directional trailer for a project with no open station is `DoD:`. (`da89cda94`)
- **doctrine** — The doctrine names the `change`, `walk`, `product-docs` and `prd-and-dod` launchers in place of `chain-development`, `chain-change`, `chain-product` and `chain-agari`. `core/doctrine/setup/kensaiapp_structure.md` lists each old launcher path among its reference-only migrations, beside the path that replaced it. (`8ec5d752c`, `7ebc2d82c`, `36fb2dd25`)
- **doctrine** — `core/doctrine/setup/kensaiapp_structure.md` names the two step tables `core/tools/chain_development.py --steps` takes `change`, for the `change` launcher, and `walk`, for the `walk` launcher. It states that the `change` launcher keeps its records as `chain-change-<project>-*` and the `walk` launcher keeps its own as `chain-walk-<project>-*`. (`423e6aef6`, `7ebc2d82c`, `333051e69`)
- **tools** — `core/doctrine/engineering/languages/swift/environment.md` states that the gate reads the macOS guest's name and shares from the guest's login job, and that a gate's caller gives none. It also states that the gate stops every guest process running from a copy before it removes the copy. (`a5adb561d`, `7ae736a94`)
- **doctrine** — `core/doctrine/flow/step_outcome_contract.md` states that a saved-red note, `- Task <N> red saved as <commit> — <reason>`, counts as a task's red when the commit it names is a non-landing commit of that task, older than its landing, with a pause of the change between the two. (`6d8016036`, `f4f137a3c`)
- **tools** — `core/doctrine/governance/versioning.md` states that the entry a merge adds to a shell file's `# Version:` lines carries the merge's description without a change's key or a path into one of the instance's projects, the parts the vendor-neutrality check would report. (`b40a11933`)
- **tools** — The Python and shell toolchain packets under `core/doctrine/engineering/languages/`, `core/doctrine/setup/kensaiapp_structure.md`, `setup_scope.md` and `shared_core_instance.md` state that kensaiapp's hooks, launchers, skills' commands and test suites run on the Python that `.python-version` names, through uv and `core/tools/locked_python.sh`. The structure map states that a pin carries the root's `.python-version`, `pyproject.toml` and `uv.lock`. (`09877ad6c`, `d010068cf`, `47e94e6dd`, `bbe1abe11`)
- **doctrine** — `core/doctrine/governance/records_name_no_machine.md` states that a record names no repository address either. No line names the `<owner>/<name>` of the repository the record is committed to, which its `origin` remote carries, and the file gives `<owner>/<repository>` to write in its place. (`068b8be3c`, `b7b25d2ef`)
- **doctrine** — `core/doctrine/setup/setting_up_a_project.md` states which part of the definition sequence each `Definition:` value walks and which setup seed it stamps, and that a no-code product is never `full`. `kensaiapp_structure.md` and `setup_scope.md` name the second seed template, `setup_seed_prd_and_dod_template.md`. (`2de6fae45`, `2fcd9747f`)
- **tools** — `core/doctrine/flow/development_flow.md` § *The stages* has a row for `changelog-line`, the Content Editor step after implementation and before code integrity. `core/doctrine/flow/folder_state_handoff.md` and `step_outcome_contract.md` state that the step is done once its report is committed on the change's branch, whether or not it changed a product file. `core/doctrine/setup/kensaiapp_structure.md` § *The what-left file — the one place a product states what is still to build* states that `changelog-line` removes an entry on the change's branch, so the removal reaches `main` in the merge that carries the wanted thing. The `Merged in` line of a removal's commit names a commit on the change's branch at which the product does the wanted thing. `readme-status` still removes an entry once its wanted thing has merged. (`4f23f0a72`, `21aaa73a4`, `2695c5e10`, `e34fe637d`)
- **tools** — `core/doctrine/setup/kensaiapp_structure.md` names `changelog-line` as the one run that removes a what-left entry, and no longer names `readme-status` or its row in the `build-idea` queue. § *The changelog* says a product's state is read from its `CHANGELOG.md` and its `docs/what_left.md`, and that a product keeps no release-notes file. `core/doctrine/README.md` says each change in `core/doctrine/` is recorded in its `CHANGELOG.md`. (`0d9b8229d`, `368ccf49a`)
- **doctrine** — `core/doctrine/engineering/testing_doctrine.md` § *A test reads nothing of the machine it runs on* states that a test depends on nothing else of the machine it runs on. It names four more things a test may not depend on, each with what the test does instead: who runs it, the system's own tools, the system's terminal and the network. A table shows which of the section's seven rules the commit-time check and the guards that run while tests run each check, and the section says neither place checks the four new ones. (`ee6dc1694`)

### Removed

- **doctrine** — `core/doctrine/setup/kensaiapp_structure.md` no longer allows a change-pipeline step a launcher of its own, in a folder nested below the change pipeline's launcher. Each step starts through the skill launcher. (`acfebc255`)
