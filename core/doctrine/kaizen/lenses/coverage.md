# Lens — coverage

**Your question: is everything that should have reached the artifact in it — and is what is in it
doing work?**

Two directions, and the second is the one that gets skipped.

**Inward — did anything drop?** Walk each source document and account for every fact that would
change what the product is, what it may do, or what it promises. Each one is either carried into a
section, or **consciously dropped with its reason recorded in the artifact itself**. A fact that is
simply absent is a finding — and so is a drop whose reason lives only in a transient file, because
that file goes away and takes the decision with it.

For a source with enumerable units — numbered clauses, a regulation, a standard, a requirement list
— reading attentively is not coverage, it is a memory. The tell that a memory is all that happened:
**which unit slipped changes between runs.** A genuinely hard clause gets missed twice; a different
one each round means nothing enumerated them. The units that hide are the ones granting something
with a condition attached — the grant reads as the point, the condition reads as boilerplate.

**Outward — is every section load-bearing?** A template section filled with words that would be true
of any product is hollow, and it is worse than an empty one: it looks answered. Ask of each: if this
were deleted, what would a reader no longer know?

**And the hardest direction — what should be here that no source would have mentioned?** The two
checks above are both source-driven: they trace inputs to the page. Neither can see a thing that
belongs in a document of this kind and that no input would ever have prompted — the bar on a metric,
the ambition the scope was cut from, the assumption every reader will make and no author stated.

You will not find these by reading, because reading finds what is written. Put the sources down and
ask what a document like this **owes its reader**, then look for each one. Where the skill names such
obligations, walk them; where it does not, that absence is itself the finding — and it will be
invisible to every other lens, which is why this direction is yours.

**Report a missing thing as a finding in its own right, not as a note.** An absence has no line to
quote and no sentence to point at, so it reads as weaker than a defect you can cite. It is usually the
opposite: a wrong sentence gets caught by the next reader, a missing one is agreed to by everybody.

**And the skill's own questions.** If the skill brings a diagnostic, check the artifact **truly**
answers each — not that a section with that heading exists.

Distinguish the two roots when you report: a fact that dropped because the skill had no capture path
for it is skill-general; one that dropped for no reason is this run.
