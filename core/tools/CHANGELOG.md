# Changelog — `core/tools`

Each entry records a change to what a user of a fresh clone installs, runs, types or reads in `core/tools/`, or in one of the root files that `core/doctrine/setup/kensaiapp_structure.md` § *The changelog — one file per product path records what changed for a user of a fresh clone* logs here. It names the project the change was made under and cites the commits that made it. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Upgrading

- **tools** — kensaiapp runs on version 0.3.0 of the telemetry package, installed from PyPI, and the README now names that version. Upgrade the copy in kensaiapp's own environment with `~/.kensaiapp/venv/bin/pip install ka_telemetry==0.3.0`, then restart a receiver that is running so it picks up the new code. (`77c0e74ce`)
- **tools** — Run `shukuba-refine` again for a station whose route report was written before this change and holds a `readme-status` row. The `build-idea` queue no longer has that row, so it refuses such a report before anything launches. (`a3fcb00e5`)
- **tools** — The Definition of Done is now the finish line, and `DoD` is not read anywhere. Let every PRD or finish-line walk end before you take it. Then, in a clone's own `.providers.toml`, rename `DoD` under `[documents]` to `FINISH_LINE`: a product-docs or prd-and-finish-line walk is refused without it. Rename each project's `dod.md` to `finish_line.md`, `dod_open_issues.md` to `finish_line_open_issues.md` and `trail/dod/` to `trail/finish_line/`. Change each project card's `**Definition:**` value `prd-and-dod` to `prd-and-finish-line`, and run the `prd-and-finish-line` launcher where you ran `prd-and-dod`. Write `Finish-line: <project> — progress: …` where you wrote `DoD: <project> — progress: …`: the builder does not refuse an old `DoD:` line, it passes it unchecked, so change any script or prompt that still writes one. Type `finish_line` where you passed `DoD` to the companion-self-answer launcher, and name the reporter `finish-line` where a skill's `launcher.md` or a `watch_agent.py --reporter` named `dod`. (`950438dee`)
- **tools** — Agari is now the Definition of Done, DoD for short, and the old name is not read anywhere. Let every PRD or DoD walk end before you take it. Then, in a clone's own `.providers.toml`, rename `Agari` under `[documents]` to `DoD`: a product-docs or prd-and-dod walk is refused without it. Rename each project's `agari.md` to `dod.md`, `agari_open_issues.md` to `dod_open_issues.md` and `trail/agari/` to `trail/dod/`. Write `DoD: <project> — progress: …` where you wrote `Agari: <project> — progress: …`. (`da89cda94`)
- **tools** — A clone must install uv for its hooks, launchers and test suites to run. Each of them runs its Python through uv, on the Python that `.python-version` at the instance root names, and stops without uv rather than falling back to `python3`. Install uv with `brew install uv` or `curl -LsSf https://astral.sh/uv/install.sh | sh`. (`3d5750513`, `4e80b5534`, `f44e52f31`)
- **tools** — In a clone's own `.providers.toml`, rename the `change` entry under `[steps]` to `open`. The step that opens a change is named `open` now, and a launch is refused when `.providers.toml` lacks the entry it needs. (`7ebc2d82c`)
- **tools** — Where you type `chain_development.py --steps`, type `--steps change` in place of `--steps development` for the change launcher's steps, and `--steps walk` in place of `--steps change` for the walk launcher's steps. `change` is the default. (`423e6aef6`, `7ebc2d82c`)
- **tools** — Run `shukuba-refine` again for a change whose route report was written before the launcher renames. The `build-idea` queue no longer reads a launcher's old name, so a row whose command names an old launcher path fails until the report is written again. (`562f0a75c`)
- **tools** — A project card's `**Definition:**` value `prd-agari` is now spelled `prd-and-dod`, the name of the walk it starts. Change each card that reads `prd-agari` to `prd-and-dod`: the walk and build-idea refuse `prd-agari`. (`dc70038d1`)
- **tools** — In a clone's own `.providers.toml`, add `changelog = "claude"` under `[steps]`. The change chain runs a new step, `changelog`, after implementation and before code integrity. A walk is refused when `.providers.toml` lacks the entry for one of its steps. (`6facff0d7`)
- **tools** — `commit_builder.py merge` refuses a merge into `main` whose branch adds no entry under `## [Unreleased]` in a `CHANGELOG.md`, and `merge --check-only` gives the same answer. Add the change's entry under `## [Unreleased]` on the branch, or pass `--user-invisible "<reason>"` when the merge changes nothing a user sees; the reason is recorded in the merge commit as `User-invisible: <reason>`. The seal's delivery takes the same declaration as a `user_invisible` field in a role's merge record. (`2c2a1536f`, `50dbe87ad`)

### Added

- **tools** — When a `specs`, `design` or `plan` run of the change chain stops with a `halt_report.md` whose halt reason is `records-owed`, the chain answers it on a project whose card reads `**Definition:** full`. It launches `product-docs` once to fold the items the report's `Raised item:` lines name. Once the sweep ends `sealed` with every item folded, it removes the change's old worktree and branch and starts the change again at `specs`. Where an item stays open, or the sweep ends any other way, the walk halts and its reason says why. On any other card, a `records-owed` report halts the walk as any halt report did before. (`4c44ddcf5`, `c48203144`, `dce07f465`, `9c6647960`)
- **tools** — A test in kensaiapp's own suites, under `core/tools/` and `core/launchers/`, now fails when it tries to open a network connection to another host or to look one up, and its failure says it opened a real network connection. A server the test starts on `127.0.0.1`, and a Unix socket, still work. No setting turns this off. (`6b63d07ff`, `46c264dc2`)
- **tools** — `chain_development.py --check-commit-shape` answers whether a draft closing-marker body would pass the chain's commit-shape check, in the chain's own words. It reads the product path off the project card, and refuses with exit 2 an input that names no change. (`2d932b698`, `1d05f0ac1`)
- **tools** — A Codex run can run a product's gate in the macOS guest. The run makes the one gate call outside its sandbox by approval, and `core/tools/gate_suite.py` puts each command it starts back into a sandbox with the internet closed. (`71c3a359f`, `c12f07a9b`)
- **tools** — `core/tools/check_record_privacy.py` runs from the pre-commit hook. It refuses a commit that adds a line naming the committing machine's home folder or login name to a record, which is a file under `system/projects/` or in any `docs/` folder. (`17f2b443f`, `ab23b5d80`, `50cd40672`, `c7e225204`)
- **tools** — `core/tools/check_test_isolation.py` runs from the pre-commit hook. It refuses a commit whose test files read the machine they run on: the home folder, a private project's folder from a test that travels without it, or a real commit handed to git. The refusal says to fix those lines on the branch. A pinned Codex run's commits meet the git hooks too. (`d12a0b308`, `c90bded3d`, `d28ec08ec`, `6d0d8ee83`)
- **tools** — Each test in kensaiapp's own suites runs with an empty home folder made for it, and the gate runs a product's suite on the host Mac with one too. (`d12a0b308`, `c90bded3d`)
- **tools** — `/bin/bash core/tools/doctor.sh` reports whether the machine has the six tools kensaiapp runs on (uv, git, podman, tart, gh and claude), each at its minimum version. It exits 1 when one is missing or too old, and `--help` lists the minimum versions. (`01d6dc6cc`)
- **tools** — The instance root carries `.python-version`, `pyproject.toml` and `uv.lock`. Together they fix Python 3.14 and the exact pytest and pytest-xdist versions that `uv run --locked pytest core/tools/ core/launchers/` runs the suites on. (`f44e52f31`)

### Changed

- **tools** — On a project whose card reads `**Definition:** full`, a `records-owed` halt now copies each raised item the step wrote in the change's worktree onto the product's main checkout before `product-docs` launches, so the sweep can fold it. The item goes to the end of the companion's *Raised from downstream* section in one commit on `main`, and an item `main` already holds is not copied again. The walk stops without writing when that checkout does not have `main` out or the companion has uncommitted changes, and when the commit fails it puts the companion back as it was. (`053f6f9df`, `90d6b0c5b`, `b71689a29`, `860632146`, `137b741e1`, `f2dbddbbc`, `0b8def79e`)
- **tools** — The chain board and the kensaiapp panel name the `product-docs`, `prd-and-dod`, `change` and `walk` launchers. The panel's line for the change a walk is on is the change's title, with no label in front, and a change not opened yet reads `next change`. `.providers.toml.example` names the new launchers too. (`8ec5d752c`, `eaea638ae`, `6ed5b7685`, `36fb2dd25`, `7ebc2d82c`)
- **tools** — The gate reads the macOS guest's name and shares from the guest's login job each time it runs, and a plan names no guest. Every path the gate reports writes the home folder as `<home>`. (`7ae736a94`, `9b4e8de09`, `9f3d86a3e`)
- **tools** — Without uv, the runner's message names everything that stops (hooks, skills' commands and launches) and says that a commit the git hooks check is refused. (`0d09e74f9`)
- **tools** — A launch that makes a new pin prepares the pin's own environment with the source host's Python before it starts, through `locked_python.sh --prepare-pin`. It installs no package and downloads no Python. A failed preparation stops the launch before it is announced. (`573270bc5`, `719793848`, `b0bc183ac`)
- **tools** — The launch entry in `core/tools/pin_run.sh`, the launch helpers and the three kaizen launch scripts (`launch-audit.sh`, `launch-fix-author.sh` and `launch-apply-packet.sh`) run their Python through `core/tools/locked_python.sh`. `locked_python.sh --check <launcher>` is the one look for uv a launch makes at its entry. (`2750f5fcb`, `4e80b5534`, `55515d42f`, `d181176eb`)
- **tools** — The `Containerfile` builds on `ghcr.io/astral-sh/uv:python3.14-bookworm-slim`, the Python the instance pins, in place of Python 3.13. (`fda7499a6`)
- **tools** — Claude Code's hooks and the git hooks run through `core/tools/locked_python.sh`, on the Python the instance pins, rather than on the first `python3` the shell finds. A pin carries the root's `.python-version`, `pyproject.toml` and `uv.lock`, and a satellite's hook commands name the host's runner. (`3d5750513`, `b16f03055`, `7d3017fb4`)
- **tools** — A walk's notifications name it after its launcher, `walk chain` for the `walk` launcher's walk and `change chain` for the `change` launcher's. (`423e6aef6`, `7ebc2d82c`)
- **tools** — `core/tools/check_record_privacy.py` also refuses a commit that adds a line naming the repository's own address to a record. The address is the `<owner>/<name>` read off the repository's `origin` remote, when that remote is on a hosting service, in any letter case. (`068b8be3c`, `b7b25d2ef`)
- **tools** — build-idea reads `full`, `prd-and-dod` or `none` from a card's `**Definition:**` line, and names those three in its refusals. A card reading `prd-agari` is refused. (`dc70038d1`)

### Removed

- **tools** — The `build-idea` queue no longer runs `readme-status` after it closes a reached station, and `.providers.toml.example` no longer lists a `readme-status` row. A `.providers.toml` that still lists one does not stop the queue. (`a3fcb00e5`, `afdc10868`)

### Fixed

- **tools** — `test_gate_suite.py` no longer fails by timing on a machine where the consumer of a pipe exits before its producer writes. A pipe in `gate_suite.py` whose producer is ended by a broken pipe, because its consumer failed first, now reports the consumer's status in place of `-13`. (`1b66e3025`)
- **tools** — `test_suite_map.py` passes in a release, which ships a `.github/` folder this instance does not hold. The suite map matches `.github/**` and runs no suite for it, as for `docs/**` and `about/**`. (`f1882585b`)
- **tools** — Nine tests in `core/tools/` no longer fail on a Linux machine that has no Python at `/usr/bin/python3`, or no `npx` and `node`. The pin-preparation tests in `test_locked_python.py` and `test_pin_run.py` run on the suite's own Python, and the skill-launcher dry run in `test_chain.py` puts stand-ins for the programs a skill requires on PATH. (`345aafc61`)
- **tools** — An approved Codex gate runs its test commands without adding a second sandbox, allowing localhost-based test setup to execute. Codex still requests approval for the gate invocation. (`f1cb5acb6`)
- **tools** — A product's browser suite that the gate runs on the host Mac finds Playwright's browsers. The empty home keeps `PLAYWRIGHT_BROWSERS_PATH` at its default unless the caller set it. (`29b8bf850`)
- **tools** — Before the gate removes a copy of a product in the macOS guest, it stops every process running from that copy, with each one's direct children. It says on standard error how many it stopped. (`4015f7d2b`, `a5adb561d`)
- **tools** — The `build-idea` queue counts a journey move as landed only once the move is in the instance's last commit, not when it shows on disk. That covers a retire, a station close, a pick, a route cut and a docs cut. (`1bcdea3f6`, `f32374252`)
- **tools** — The chain accepts a task's red that an earlier run saved under another label when a saved-red note names it. The named commit must be a non-landing commit of that task, older than its landing, with a pause of the change between the two. (`6d8016036`, `f4f137a3c`, `0ee2a13bc`)
- **tools** — `core/tools/locked_python.sh` refuses by name a root that holds no `pyproject.toml`, since that root is not a kensaiapp instance. (`6d0d8ee83`)
- **tools** — A walk started from a checkout whose path holds a space no longer ends `no_runnable_command`. The chain keeps the core's path as one word in the launch commands it builds. (`237668bb7`)
- **tools** — The chain engine advances each launch once. Starting, advancing and stopping a walk each hold a lock on its state file, and two saves made at once both complete. (`921ea7573`, `aa6da80c5`, `269e1d985`)
- **tools** — A Codex run sets `UV_CACHE_DIR` to a folder its sandbox can write, so the runner no longer exits 2 inside every Codex step. (`2aab066cd`)
- **tools** — `commit_builder.py merge --bump` writes a shell file's `# Version:` note without the parts the vendor-neutrality check would report, such as a change's key. A merge's description can no longer turn `main` red through that note. (`85487ab71`, `b40a11933`)
