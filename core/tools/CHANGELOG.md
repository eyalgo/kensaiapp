# Changelog — `core/tools`

Each entry records a change to what a user of a fresh clone installs, runs, types or reads in `core/tools/`, or in one of the root files that `core/doctrine/setup/kensaiapp_structure.md` § *The changelog — one file per product path records what changed for a user of a fresh clone* logs here. It names the project the change was made under and cites the commits that made it. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

### Added

- **product-development** — `seal_audits.py` is a new tool with two commands. `join`, given the change worktree, the key and the commit builder, merges every local branch named `<key>__audit-<step>` into the change branch, one merge commit per branch, and prints the list of branches it joined. A branch already in the change branch counts as joined and adds no commit. A failed merge is aborted and the tool exits non-zero naming `merge-conflict` or `merge-hook-failed`. `remove`, given the join's report and the delivery's outcome, deletes only the branches that join report names, with their worktrees, and only when the delivery outcome reads `"status": "ok"` with `"audit_cleanup_eligible": true`. It removes nothing and exits `1` with `teardown-failed` when any of them has uncommitted work, carries a commit `main` lacks, or has no single worktree of its own. It never forces a deletion. (`edc11be08`, `3311c90b1`, `cf0aadc86`)
- **product-development** — `change` and `walk` pass QA's step, `red-behaviour`, on a QA record that says nothing the change states can be reached through the product's recorded way in. On the re-run an accepted ask starts, the record counts only when a commit made after the ask changed it, and the walk then returns to the step that asked.
