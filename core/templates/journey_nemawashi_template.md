# 根回し Nemawashi — <project>'s seedbed

*The **project**-level seedbed: the ideas that carry this product toward its 上がり Agari
(`system/projects/<name>/agari.md`) — roots laid before the road. One is **active** at a time; the rest
are **candidates**. Scoped to this product; mirrors the instance Nemawashi (`system/nemawashi/`).
`project-stamp` stamps this into `system/projects/<name>/journey/nemawashi/README.md`.*

---

**This is a folder, not a queue.** Each idea is its own file — `<YYYY-MM-DD>_<slug>.md` — seeded
directly in `journey/nemawashi/` as it arises. An idea a `shukuba-refine` run has reported on is its
own folder instead, `<YYYY-MM-DD>_<slug>/`, holding `seed.md` (the idea itself, unchanged) plus a
`<unit-key>_report.md` and `<unit-key>_recommendations.md` per reviewed unit, sealed or halted — nothing converts
the file form until the first report lands. One idea per file-or-folder, so a finished idea is moved
whole either way.

**Pick one → see only it.** The candidate pool lives in `unpicked/` — any number of ideas, whether or
not one is active. Picking an idea lifts it out of `unpicked/` to the root, leaving that one idea alone
here; no other candidate moves. An **empty root means no idea is active**.

**The active idea carries a dynamic checklist.** The picked idea's file holds a checklist of the
stations it will pass through — grown and refined as the work reveals them, not fixed up front. Each
unchecked item, when you work it, opens the current 宿場 Shukuba (a full station: reached-when +
guardrail). When that station is reached, its Shukuba file moves to `shukuba/trail/` and you check the
item `[x]` here. (There is no separate plan folder — the checklist *is* the plan, living with the idea.)

**Lifecycle.** **Seed** an idea → pick it (lifts it out of `unpicked/` to the root; nothing else moves) →
walk its checklist one station at a time via 宿場 Shukuba + 飛び石 Tobiishi → when every item is checked
the idea has **ripened**: move its file to `trail/` — skill: `nemawashi-retire`, which restores
nothing. Never strike an idea through. `journey/nemawashi/trail/` is the record of ideas that ripened
into work — here that means the checklist walked to the end, which is a project's only route to it
(`<CORE>/docs/michi_agari.md` § Quick reference owns the criterion and the one other route, which is
the instance seedbed's).

**An idea that is killed goes to `drop/`, not `trail/`** — skill: `nemawashi-drop`. A candidate ruled
out before it was ever picked never ripened, and `trail/` is the record of ideas that did. Both
are records and the file survives at a resolvable path either way; they differ in what they say
happened.

**One word, one sense.** *Seed* is how an idea gets here; *drop* is what happens to one that is
killed. A record already in `trail/` or `drop/` may open with a word this seedbed no longer uses —
the folder it sits in is the record, not the wording inside it.
