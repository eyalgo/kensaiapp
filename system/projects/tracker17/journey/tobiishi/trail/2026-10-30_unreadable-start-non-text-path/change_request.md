# Change request — 2026-10-30_unreadable-start-non-text-path

---

**Request:** When the tracker's saved data sits at a path holding a byte that is not text and the data cannot be read, a start fails today: the unreadable-data page is built first (`web.UnreadableSite.__init__` encodes it as UTF-8) and the unreadable console line is printed after it, and both raise `UnicodeEncodeError`, so the tracker does not start. Make that start print the unreadable line and serve the unreadable-data page, each naming the path in the one form `products/tracker17/docs/CONTENT.md` § *A path the tracker prints* fixes: the byte as a backslash, an x and two hex digits (`\xe9`), nothing else in the path changed and no replacement mark, so a path decoded from `b'/tmp/caf\xe9/data'` shows as `/tmp/caf\xe9/data`. The ready start already does this through `main._shown_location`; bring the unreadable line and the page to the same form. Add tests under `products/tracker17/tests/`: one builds the unreadable line for `Path(os.fsdecode(b'/tmp/caf\xe9/data'))` and holds that it contains `/tmp/caf\xe9/data` (four characters `\xe9`), no U+FFFD and no character in U+DC80–U+DCFF, and that `.encode('utf-8')` does not raise; one builds `web.UnreadableSite` for that location and holds that it does not raise and that a request to the root answers with a page whose body carries the path in that form; and one starts the tracker through the start function on unreadable saved data at that location, with the file system calls faked (or skipped with the reason stated, as the ready start's valid-file case is, since this machine refuses the byte in a directory name), holding that the line is printed and the page is served. The line and page tests fail on `main` before the change (`UnicodeEncodeError` or a failed assertion on the path text) and pass after. A path with no such byte must print the line and the page exactly as before, so the existing unreadable-line and unreadable-page tests pass untouched, and the full suite passes as the project's `Test command:`.

Sizing: one capability (the unreadable start on such a path, its line and its page being one behaviour, SDD § 6 S-8, and the page built before the line prints), one merge; the acceptance boundary is the station's reached-when 1 to 6. The failed-action console message is the seed's next item and stays out. Hold the path form to `CONTENT.md` with no new wording and no other message text changed. No document changes (FDR R-2, R-24 and R-25 hold as written). Saved data must never be written, replaced or deleted by this start or by serving the page (SDD SD-4); where the saved data lives (FDR R-16), the location the claim, the load and the saves use, the page's controls, the second-tracker refusal and the lock must not change, only how the location is shown.
