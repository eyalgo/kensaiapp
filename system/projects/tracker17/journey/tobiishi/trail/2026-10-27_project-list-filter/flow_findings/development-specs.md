- **[non-blocking · change-local · altitude]** Rules fix a layering and a storage mechanism, not an observable property. CP-406 says each refusal type is "defined and raised in `domain` and handed to `web` through `application`"; CP-413 says a filter "never reaches the saver"; CP-418 says the fixture is "saved in a location of its own inside the run's temporary directory". Each states where code or data lives. Where: `change_spec.md §Rules` CP-406, CP-413, CP-418 (and the `web/routes.py:758-761` anchor in `§Locked Answers` Gap 4). Detail: the records (SDD OB-4, NFDR QC-5/QC-8) do bind this, and Gap 12 records the reason, so it is not silent. Even so, the observable form ("no part tells one refusal from another by reading its message"; "saved data is byte-for-byte unchanged") is already in the same rules, and layer placement is the design's to realize. Direction: state the property and cite the record; leave placement and the saver anchor to design.

- **[non-blocking · change-local · handed-down constraint — enacted]** The spec prescribes the shape of tests the test-design step owns. CP-415 ("a clock handed in, with no name patched in a product module"), CP-416 ("run in one process with the clock and the saver handed in"; "one test per refusal … asserting the reason shown, the focus, and the saved data unchanged"), and CP-422 (which harness cases to feed, e.g. "a total at 1.0 second with both parts under it") decide test shape and case lists. Where: `change_spec.md §Rules` CP-414 to CP-416, CP-422. Detail: the request names AC-12, AC-13 and AC-14 tests, and the Examples floor is fine; but fixing test construction and per-case assertions in rules leaves design nothing to decide. Direction: state the property each test must establish (AC-12 one per refusal; AC-13's three cases agree with the marker) and let design shape the tests.

- **[non-blocking · change-local · coverage]** The rules never say how "no value" is sent for a field. CP-394 says each field takes "one value, or none", CP-396 says "a field with no value narrows nothing", but CP-404 refuses any Status or Priority value "outside the four" and any Overdue value "other than the one its control sends". A page that runs no script (CP-411) submits an untouched select or date as an empty value, which CP-404 reads as outside the four. Where: `change_spec.md §Rules` CP-394, CP-396, CP-404; Examples has no row for a blank field in the address. Detail: the address is the contract (CP-399 reload, bookmark), so whether `status=` is "no value" or a refusal is observable, and it is a rule-implied edge the Examples floor misses. A downstream test or design could pick either and satisfy the spec. Direction: state that a blank value counts as no value (or refused), and add the Example.

- **[non-blocking · change-local · evidence that could have failed]** The claim in CP-423 that "no other existing test is changed to fit" rests on probes that ran only `tests/architecture/` and `tests/integration/test_timed_run.py`. The page change (controls on every project page with tasks) was never run against the page and end-to-end tests: Verified Claims row 6 covers only the two no-task pages and was settled by reading their source. Where: `change_spec.md §Verified Claims`, rows 5 to 6; `§Rules` CP-393, CP-423. Detail: a prediction about what the existing page suite decides was derived by reading, and a stand-in controls block (as the stand-in filter was for the timed run) could have run it. A project page with tasks may carry form-count or landmark assertions the new controls break, which would add tests to CP-423's closed list late. Direction: run the existing page and e2e tests against a stand-in controls block and record what came back, or narrow CP-423's "no other" to what was run.
